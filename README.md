# X行星之谜 · 推理工作台

一个**零运行时依赖**的网页版《X行星之谜》（*The Search for Planet X*，Ben Rosset & Matthew O'Malley 设计，Foxtrot Games / Renegade 出版）推理工作台。普通对局由玩家自己推理，不提供自动解题或候选世界建议。

三个开局入口：

| 玩法 | 棋盘与人数 | 结果从哪来 |
| --- | --- | --- |
| **记录模式**（`record`，默认） | 标准 12／专家 18 扇区；可离线单人，也可联机（至少 2 人开局） | 配合官方 app，手动填写观测、线索、评审、定位判定和终局答案 |
| **内置谜题**（`builtin`） | 标准 12／专家 18 扇区，**1–4 名玩家（含房主）** | 服务端生成原创谜题，回答查询并判定对错。可另加 0–3 个启发式 Bot，Bot 只占内置座位 |
| **新手教学**（创建时 `tutorial`） | 固定标准 12 扇区、1 名真人 + 1 个脚本 Bot、每人 4 条初始线索 | 真人使用正式行动控件；点「观看 Bot」按固定脚本演示到定位与结算 |

`playMode` 是玩法，`modeId` 是棋盘（`standard`／`expert`），都在**创建之前**选择。进行中的记录局不能改成内置局。内置单人局也是服务器房间，需要服务在运行。内置局开始后锁定玩家名单；**观战**可以中途加入，不占 4 个游戏名额（一桌最多 12 名观战）。

> 这是**非官方粉丝项目**，使用自制界面、图标与原创内置谜题，不是官方 app，也不包含官方谜题库。

## 快速开始

不需要 `npm install`。Node 18+ 即可。

| 系统 | 启动 | 关闭 |
| --- | --- | --- |
| **macOS** | 双击 **`mac一键启动.command`** | 双击 **`mac一键关闭.command`** |
| **Windows** | 双击 **`Windows-start-server.cmd`** | 双击 **`Windows-stop-server.cmd`** |

也可以用命令行：

```bash
node start.mjs           # 本机 + 局域网
node start.mjs local     # 只有本机
PORT=5180 node start.mjs # 换端口（被占用时提示，不会抛 EADDRINUSE）
node start.mjs --open    # 启动后打开浏览器
node stop.mjs            # 关闭本项目登记的服务
node tests/all.test.js   # 全部回归测试
node audit/official-rules.audit.mjs
```

启动窗口会打印本机地址和局域网地址。重复启动会复用本项目已在同端口运行的服务，不会清空房间。关闭脚本只结束**当前项目目录里启动器登记的服务**。直接执行 `node server.mjs` 的旧进程没有登记，请在原终端按 Ctrl+C。

**这个窗口就是服务器。** 关闭窗口、Ctrl+C 或一键关闭都会清掉内存里的全部房间（含单人内置局和教学局）。刷新原标签页且房间仍在时，会按身份重连。`.planetx/` 只保存本机控制端口和启动令牌，不是存档，已加入 `.gitignore`。

`tests/all.test.js` 为每个测试文件单独起进程。完整测试需要能监听本机临时端口。受限环境可用 `PLANETX_TEST_TRANSPORT=memory node tests/server.test.js`（`tests/client.test.js` 同样）；这不等于真实网络验收。

### 联机

| 场景 | 做法 |
| --- | --- |
| 同一 Wi-Fi | 打开 `http://<局域网IP>:5173/` → 一人「联机 → 创建房间」→ 其他人用 6 位房间码加入 |
| 一台电脑试双人 | **Ctrl+N 开新窗口**。身份按标签页隔离。不要复制标签页，那会把身份一起复制过去 |
| 异地 | 走私有网络，例如 Tailscale，或 `cloudflared tunnel --url http://localhost:5173` |

这是明文 HTTP，访问控制就是 6 位房间码。同一 Wi-Fi 可以用，不要把端口直接映射到公网。Windows 防火墙拦入站时，用管理员 PowerShell：

```powershell
New-NetFirewallRule -DisplayName "Planet X console" -Direction Inbound -LocalPort 5173 -Protocol TCP -Action Allow -Profile Private
```

## 开局

1. **选玩法、棋盘、初始线索数。** 房主统一选全桌 **0／4／8／12** 条，默认 4。创建前和大厅里都能改，开局后锁定。教学固定为标准盘、4 条，没有人数和线索选择。
2. **开始游戏。** 记录房间至少 2 人；内置房间 1–4 人。开局时所有人还在同一格，先手在入座玩家中随机，不是固定房主。之后棋子再落到同一扇区时，按到达先后，先到者优先。
3. **开局准备。**
   - **内置**：按统一数量自动分发每人不同的私有排除线索，标到本人星图，再确认准备。不能改数量或重发。
   - **记录**：每人填写规定数量的不同初始排除线索（0 条则确认无线索）。房主另填 A–F 课题名和会议名称（标准盘扇区 10，专家盘 7／16）。线索不为 0 时还要填自己的初始线索。
4. **行动。** 累计耗时最少的人先行动；同扇区时先到者优先，因此同一个人可以连续行动。

初始线索只会是「某扇区没有小行星／彗星／气体云／矮行星」。不提供空域信息，也不直接排除 X 行星；两种模式都不会发「非质数扇区没有彗星」这类基础规则已经知道的信息。只有服务端接受本人的开局信息后，线索才写上星图。

内置研究 A–F 每题一条事实，名称只显示一种或两种普通天体，不提前泄露关系或范围。六个命题不重复。基础规律、研究、会议和充分的勘测／扫描合在一起唯一确定完整棋盘；只读完六题不能直接解出全部位置。

| 命题示例 | 线索形式示例（不是当前对局的线索） |
| --- | --- |
| 小行星 | 所有小行星都位于一段不超过 5 个连续扇区内。 |
| 彗星和气体云 | 没有任何彗星与气体云正对。 |
| 小行星和彗星 | 至少有一个小行星与某个彗星相邻。 |
| 气体云和矮行星 | 每个气体云都位于至少一个矮行星的 3 个扇区以内。 |

连续范围不指定起点，可以跨过最后一格和第 1 格，N 是上限。相邻是左右一格。正对是相隔半圈（标准盘 6 格、专家盘 9 格）。N 格以内按最短环形距离，包含恰好 N 格。「至少一个」包括全部满足，不是「恰好一个」。

### 专家盘

18 格是 **4 小行星、2 彗星、2 气体云、4 矮行星、5 空域、1 X 行星**。彗星只在 2／3／5／7／11／13／17 号。4 颗矮行星落在**恰好 6 格的连续带里，带的两端都是矮行星**。每颗小行星邻接另一颗小行星，每片气体云邻接真正空域，X 不邻接矮行星。可见天区 9 格。矮行星论文每篇 2 分。学术研究每阶段最多 2 篇，两篇可以是不同天体。

7／16 号会议各给一条 X 与一种普通天体的关系。两场尽量针对不同天体，不把同一事实的两种说法各发一场。在该天体都已放好之后，优先留下大约 3–5 个还能放 X 的扇区；合在一起仍要能区分同一观测下的 X 与空域对调。标准盘只有一场会议，同样按这个强度来选。独立枚举有 **1,138,272** 张基础合法专家盘。出题按每种局部摆法还能完成的合法盘数量加权，使每张盘机会相同，再认证会议与研究线索；配不出就重抽，最多 256 次。不在每次建房时展开全部棋盘。

标准合法盘 **4,446** 张，其中 **18** 张在完整观测下仍不能靠上述关系会议区分，已从出题池排除。现在从剩余 **4,428** 张均匀抽题。

### 内置 Bot 与难度星

创建内置局时可选 **0–3 个 Bot**。Bot 只看自己的 `viewFor` 视图：自己的初始线索、勘测、扫描、已获得的研究／会议，以及公开日志。它不读 `room.puzzle`，也不读别人的私有结果。每次行动都走 `applyRoomAction`。记录模式和教学不接受 `withBots`。教学里的「领航员」是固定脚本，不是这套启发式 Bot。

内置局创建后会在后台用**单人 Bot、4 条初始线索**模拟一局，给出 **1–5 星**。星级不随本桌人数或所选线索数改变。评估还在进行时显示「难度评估中…」。模拟用完时间预算时星级偏高，仅供参考。断点可用 `GET /api/puzzles/difficulty?modeId=standard|expert` 查看；没有对外的难度计算 POST。

### 教学

10 章：初始标记、勘测、天窗与同格顺序、论文、扫描空域、研究、正确评审、会议与错误罚时、推理标记、定位和最后机会计分。错选只解释当前目标，不扣时间。刷新可恢复当前步骤。重新教学另开房间。退出回到原来的普通房间或单机记录。

## 界面

桌面端左侧是推理线索、研究课题、学术研究和会议，中间是星图，右侧是当前行动，底部通栏是行动历史和积分。中屏是星图 + 行动，窄屏按星图 → 行动 → 参考资料排列。

- **X 行星会议**卡从开局就列出每次会议的标题、扇区和公开状态。未触发时不展示内置线索正文。
- **行动历史**一列一名玩家、一行一次实际记录，按日志顺序，不把不同玩家的第 N 次行动拼成同一回合。自己的结果在单元格里展开；别人的私有结果不进 DOM。
- **积分详情**每人两行：各天体及单位分、最早提交奖励、定位、合计。
- 顶栏可以**存档／加载存档**。单机直接恢复对局和标注；联机或内置房间若服务上已没有该房间，可先恢复再选座位。导出文件含谜底和令牌，不要发到公开场合。服务重启后，进行中的房间只能从这份手动存档恢复，没有自动落盘。

## 行动

两种玩法都先选行动和目标。记录模式再手填官方 app 的结果；内置模式只提交查询，服务端返回本人可见的结果。

| 行动 | 怎么选 | 记录模式 / 内置模式 | 耗时 |
| --- | --- | --- | --- |
| **勘测** | 选天体，在星图点起点和终点；整段必须在共享天窗内 | 手填数量 / 自动得到数量 | 1–3 格 4、4–6 格 3、7–9 格 2 |
| **扫描** | 一个可见扇区；每人最多 2 次 | 手选结果 / 自动得到小行星、彗星、气体云、矮行星或空域 | 4 |
| **研究** | 尚未研究的 A–F | 房主填课题名、本人抄线索 / 课题名预设，查询后得到私有线索 | 1 |
| **定位 X 行星** | X 的扇区，以及左右邻居的真实天体 | 手填判定 / 服务端核对三项 | 5 |

标准盘可见 6 格，所以 7–9 格勘测只在专家盘出现。彗星勘测的起止都必须是可能含彗星的扇区：标准盘 **2、3、5、7、11**，专家盘再加 **13、17**。自己连续两次行动不能都是研究。

界面上没有「等待 1 个时间单位」按钮。记录模式房主的「跳过当前玩家」在普通行动阶段相当于让该玩家等待 1 格；内置模式不能跳过。论文提交、最后机会和揭示不花时间。

**空域**是观测结果，可能是真正空域，也可能是 X 行星。内置规则里的「真正空域」才是没有天体的扇区。查到空域不会自动确认真正空域，也不会自动排除 X。

### 星图标注

点天体图标，在 **可能存在／确定存在／不存在** 里选。图标按扇区旋转；非质数扇区不画彗星。标注存在本机浏览器，按房间和身份分开，刷新还在，不跟设备同步。

太阳旁的虚线轨道上有一颗**地球**，停在共享可见半圆的角度中线上，跟随天窗而不是某一位玩家。标准盘每格 30°，专家盘每格 20°。它只表示天窗方向，不能点击。

专家盘会根据手写标注列出仍可能的**矮行星带**（恰好 6 格、两端都是矮行星，可跨过 18 和 1）。记录模式还会在星图上淡淡标出仍可能落在某条带内的扇区。这只排除与你的标记矛盾的带，不替你填答案。

位置显示「第 N 圈／第 M 格」，时长显示「N 个时间单位」。一个时间单位是棋子前进一格。天窗跟着**最靠后**的那枚棋子走；有人冲到前面不会移动天窗，也不会触发会议或学术研究。

### 学术研究

论文不是随时可做的行动，由时间轨触发。

1. **触发。** 共享天窗起点**离开**学术研究标记时进入阶段。进入 3 号不触发，从 3 号走到 4 号才触发 3 号。离开 12／18 号回到 1 号也会触发。一次跨过多个标记会按顺序排队。
2. **同时秘密选题。** 每人同时选定篇数和每一篇的天体。标准盘最多 **1** 篇，专家盘最多 **2** 篇，两篇天体可以不同，也可以相同。选 0 篇表示本阶段不交。选定后不能改。别人看不到你的篇数和天体。新的阶段默认不选中任何天体。
3. **再按顺序只选扇区。** 所有人都选定后，耗时最少的人先选扇区；同扇区先到者优先。轮到你时，天体已经定好，只选还能放下该天体的扇区。两篇必须落在不同扇区。别人只看到扇区。
4. **轨道 4-3-2-1。** 新论文落在最外圈的 4。本阶段结束时，所有未评审论文向内走一格，零提交也会推进。同一阶段的论文一起移动。
5. **同行评审。** 只处理到达轨道 1 的论文，按扇区编号从小到大。记录模式由作者或房主填写 app 判定；内置模式由服务端自动评审。
   - **正确**：该扇区对全桌公开，之后不能再对这个扇区交论文。
   - **错误**：被否定的天体也公开；每篇新判错的论文让作者前进 1 格。

同一阶段、同一扇区只能交一次。已公开的扇区不能再交。彗星只能交在可能含彗星的扇区。空域不能作为理论。某种天体的标记用完就不能再选它；交对或交错都不退回。标准库存是小行星 4、彗星 2、气体云 2、矮行星 1；专家盘矮行星是 4。

离线记录局仍在理论卡片上同时选扇区和天体，用「完成本阶段」结束，不走房间里的秘密选题。单人内置局和多人房间一样，先秘密选题再只选扇区。

### 积分与终局

| 项目 | 分数 |
| --- | --- |
| 评审确认正确的论文 | 小行星 2 · 彗星 3 · 气体云 4 · 矮行星 4（专家盘矮行星 2） |
| 最早阶段在某扇区交对的人 | 每个这样的扇区 +1，同阶段各作者共享 |
| 第一个正确定位 X | +10 |
| 最后机会里正确定位 | 落后首次发现者每格 +2（1–5 格对应 2–10 分） |

总分相同则比定位分，再比最早提交奖励，仍相同则并列。

正常定位花 5 个时间单位。内置模式核对扇区和左右邻居，不采信客户端自报的对错。首次正确后冻结天窗。仍落后的玩家各有一次最后机会：落后 1–3 格最多 1 篇，落后 4–5 格最多 2 篇；也可以定位或放弃。这些选择不移动棋子。

最后机会结束后，内置模式自动揭示并计分。记录模式由房主按 app 填完整棋盘。未评审论文按完整答案结算，不再追加处罚。

### 时间轨事件

会议和学术研究看的是共享天窗起点**离开**标记扇区，不是走到标记上，也不是按个人行动次数。

| 棋盘 | X 行星会议 | 学术研究 |
| --- | --- | --- |
| 12 扇区 | 扇区 **10**，1 次 | **3、6、9、12** |
| 18 扇区 | 扇区 **7、16**，2 次 | **3、6、9、12、15、18** |

内置会议到点自动公开，此前正文不下发。记录会议由玩家把 app 原文抄进来；房主开局时预填的文字可以带进输入框。会议不耗时，也不挡住普通行动。

记录模式可以用「天窗 ◀ / ▶」对齐实体版，不耗时。内置模式不能校准、不能撤销、不能手动评审或手动开会，也不能改课题和会议。

## 谁看得到什么

**全桌共享：** 每人的棋子和耗时、共享天窗、行动日志里的范围和课题编号（不含结果）、论文扇区和轨道、已公开的评审、已发布的会议、定位成功或失败、课题名称、是否完成开局准备。

**只有本人（观战者除外）：** 勘测数量、扫描天体、研究正文、初始线索、未公开的论文天体、定位时提交的扇区和左右邻居。

观战者能看到所有人的行动结果，不能行动，不占游戏名额。别人的私有字段不会放进你的 HTTP／SSE 快照。完整答案在服务端 `room.puzzle` 里，揭示前不进客户端。

同一扇区的棋子按顺时针区分先后：后到者在前，先到者在后。累计耗时相同且同扇区时，先到者先行动，也先在学术研究阶段选扇区。

房间在服务器内存里。身份在浏览器 `sessionStorage`：刷新会重连，两个标签页是两个玩家。临时网络错误不会删掉身份；只有房间失效或身份错误才清令牌。HTTP 和 SSE 用递增的 `revision`，迟到的旧快照不会把局面倒退回去。

## 房间 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/modes` | 棋盘、`playModes`、`builtinBoards`、`initialClueCounts`、教学配置、`withBots`（内置 0–3） |
| `GET` | `/api/puzzles/difficulty?modeId=` | 该棋盘已有样本数和星级断点 |
| `POST` | `/api/rooms` | `{name, modeId, playMode, initialClueCount, withBots?}` |
| `POST` | `/api/rooms/:id/join` | `{name, spectator?}` |
| `POST` | `/api/rooms/restore` | 用手动存档恢复内存中已消失的房间 |
| `GET` | `/api/rooms/:id/view?token=` | 该玩家的脱敏快照 |
| `GET` | `/api/rooms/:id/stream?token=` | SSE，每次变化推一份视图 |
| `POST` | `/api/rooms/:id/action` | `{token, action}` |

扇区索引从 **0** 开始，界面编号从 **1** 开始。令牌可以放在请求体、查询串或 `x-room-token` 头。

内置查询只提交目标，服务端按 `room.puzzle` 重算，不采信客户端附带的结果：

| kind | 客户端提交 | 服务端产生 |
| --- | --- | --- |
| `survey` | `type, start, size` | `count` |
| `target` | `sector` | `apparent` |
| `research` | `topic` | `name, text` |
| `locate` | `sector, left, right` | `correct` |

`conference`／`nudge`／`review`／`undo` 只属于记录模式。`theory`／`theory-complete` 只用于离线记录局。所有房间（含单人内置局）的论文用 `research-declare` 和 `research-submit`。

| kind | 谁 | 说明 |
| --- | --- | --- |
| `start-game` | 房主 | 大厅进入开局准备 |
| `set-initial-clue-count` | 大厅中的房主 | `{count}`，开始后锁定 |
| `setup` | 任何人 | 记录模式交规定数量的本人线索；房主还可交课题名和会议。内置模式只确认已分发的线索 |
| `research-declare` | 学术研究阶段的任何人 | `{phaseId, objectTypes, count?}`。数组长度就是篇数。只传 `count: 0` 表示不提交。一人一次 |
| `research-submit` | 轮到的那位 | `{phaseId, sector}`。天体用申报时的下一篇 |
| `skip-turn` | 记录模式房主 | 跳过当前玩家；学术研究阶段等于放弃剩余篇数。内置模式拒绝 |
| `final-theories` | 当前最后机会的玩家 | `{theories:[{sector, objectType}]}`，整批提交 |
| `final-pass` | 当前最后机会的玩家 | 放弃；也可以用费用为 0 的 `locate` |
| `reveal-objects` | 记录模式揭示阶段的房主 | `{objects:[...]}`。内置模式自动揭示 |

教学视图是 `playMode: 'builtin'` 再加当前 `tutorial` 步骤。真人行动要带当前 `stepId`。教学房间不能加入，Bot 令牌不会发给浏览器。

## 代码结构

```
server.mjs                 静态文件 + 房间 API（HTTP + SSE）+ 难度星后台计算
server/puzzles.js          双棋盘生成、约束校验、初始线索
server/expert-puzzles.js   专家盘均匀抽样、会议认证、有预算的精确求解
server/research.js         研究谓词、课题名、中文线索
server/bot.js              内置启发式 Bot（只读自己的视图）
server/bot-controller.js   内置局里驱动 Bot 行动
server/difficulty.js       单人 Bot 模拟、综合分、1–5 星断点
server/difficulty-cache.js 难度缓存（data/difficulty.json，按 Bot 版本失效）
server/tutorial.js         固定教学盘和脚本 Bot
server/local-control.js    仅本机的启动控制通道
start.mjs / stop.mjs       启动与关闭
public/src/                纯逻辑，Node 里直接测试
  rules.js                 成本、事件、库存、计分常量
  console.js               离线记录引擎
  room.js                  房间、玩法边界、脱敏视图
  score.js                 计分与胜者
  dwarf-belt.js            记录模式专家盘的矮行星带辅助
public/ui/                 无框架 DOM
tests/                     每个文件独立进程
```

- 隐藏答案只在 `room.puzzle`。生成器不是客户端解题器。
- 每人的耗时来自自己的行动记录。已结算的论文阶段不能单条撤销。
- 勘测和扫描用全桌共享天窗（`windowTime`），不用行动者自己的时钟。
- 脱敏在服务端完成。观战者是唯一能看到他人结果的身份。
